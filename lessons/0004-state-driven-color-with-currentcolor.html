Issue #271 · Tailwind CSS · Color lesson

Let state choose a color; let inheritance distribute it

The goal is to make one boolean control a coherent visual state without styling the icon and number separately. This requires three ideas: inherited CSS color, SVG currentColor, and complete Tailwind class names selected by JavaScript.

text-* sets the CSS color property

Despite the word “text,” a Tailwind class such as text-orange-600 sets the CSS color property. That property is inherited: descendants use the parent's computed color unless they set their own. 

<span className="text-orange-600">
  <span>Alert</span>
  <span>7</span>
</span>

Both inner spans become orange because neither overrides color. The parent is the owner of the shared visual state.

A label and number must always share one state color. Where is the strongest ownership boundary?

currentColor lets an SVG join the inheritance chain

SVG shapes have properties such as stroke and fill. Setting either to the CSS keyword currentColor tells the shape to use the element's computed color value. 

<span className="text-orange-600">
  <svg>
    <path stroke="currentColor" />
  </svg>
  <span>7</span>
</span>

The text inherits color normally. The path explicitly asks for that same value through currentColor. One class can therefore tint an icon and adjacent text as a unit.

This is not an assumption about all icon libraries. In this repository, HugeiconsIcon defaults its color to currentColor, and the Fire02Icon paths use stroke: currentColor. That is the evidence that inheritance will work here.

Foreground tint and background wash are different operations

A text-* utility changes the inherited foreground color. A bg-* utility paints the element's box. If a design calls for a tinted pill, it may use both: background on the wrapper, foreground for its contents, plus padding and a radius to make the painted box visible.

Decide which visual property communicates the state before choosing utilities. “Make the flame lit” may mean changing the foreground only. “Give the whole badge a wash” means the box background is also part of the state. These should not be conflated just because both are colors.

React chooses the class; Tailwind supplies its CSS

Tailwind has no knowledge of logged_today. React evaluates ordinary JavaScript during rendering and chooses a class string. Tailwind has already generated the CSS for class names it found in the source. 

const tone = enabled ? 'text-orange-600' : 'text-stone-500';

return <span className={tone}>...</span>;

Keep each alternative as a complete class name. Tailwind scans source files as plain text; it does not evaluate template-string fragments to discover every possible result. 

A. on ? 'text-orange-600' : 'text-stone-500'
B. `text-${on ? 'orange' : 'stone'}-600`
C. { color: on ? 'orange' : 'gray' }
Which version gives Tailwind two complete, detectable class names?

Theme tokens are the project's color vocabulary

This repository maps CSS variables to Tailwind color utilities in frontend/src/styles.css. A declaration such as --color-example: var(--example) makes utilities including text-example and bg-example available.

The variable can change between :root and .dark while the utility name remains stable. Choose a project token by its design role rather than copying a raw hex value into the component. Then inspect both themes; a foreground/background pair that works in light mode is not automatically legible in dark mode.

Transfer it to the streak

Apply the model without copying a finished component:

  1. Identify the lowest element that contains both the icon and count.
  2. Verify from the rendered SVG or library source that the icon uses currentColor.
  3. Find the repository color tokens representing the lit and unlit visual roles.
  4. Map each logged_today value to one complete Tailwind class string.
  5. Put that state class on the owner from step 1 and avoid repeating it on the children.
  6. Check both states and both color schemes before deciding whether foreground is enough.
