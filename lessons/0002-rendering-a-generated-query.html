Issue #271 · React + TanStack Query · Lesson 1

Render one generated query

Your first frontend win is intentionally small: make a Streak component that asks for today's streak and renders the returned count only after the request succeeds. Styling, tests, stories, and mutation invalidation come after this data-flow seam works.

The mental model

A React component is a JavaScript function that returns markup. A query hook gives that function a changing snapshot of one server request: first pending, then either error or success. The component's job is to map each snapshot to output.

PendingReturn null.
ErrorReturn null.
SuccessRender flame + count.

Returning null is React's ordinary way to render nothing. Here it implements two product decisions from the issue: avoid a false zero while loading, and never let decorative streak data take down the reading list.

Read the generated interface, not its machinery

At baseline commit 96451a54, Orval has already generated everything the component needs in api/generated/insights/insights.ts. You do not need to understand its overloads or write useQuery yourself. The public surface is: 

useInsightsGetStreak({ date })

// successful data:
// { count: number; logged_today: boolean }

The generated hook builds this cache identity: ['/api/insights/streak', { date }]. That is why passing the date once supplies both the HTTP parameter and the date-specific query key required by issue #271.

Boundary: call the generated hook; do not import TanStack's useQuery, call Axios, or hand-write a query key inside Streak.

One endpoint produces a family of exports

The repeated GetStreak names are not competing ways to fetch different streak data. They are layers generated for the same OpenAPI operation. Classify them by prefix and return type:

Generated export Its job Use here?
insightsGetStreak Make the raw HTTP request and return a promise. No; it does not give the component reactive query state.
getInsightsGetStreakQueryKey Build the cache identity. Later, when invalidating stale streak data.
getInsightsGetStreakQueryOptions Package the key and request function for TanStack Query. No; the generated hook already consumes it.
InsightsGetStreakQueryResult Describe a TypeScript type; it does nothing at runtime. No.
useInsightsGetStreak Run useQuery and return pending/error/success state. Yes.
useInsightsGetStreakSuspense Delegate pending and error handling to surrounding boundaries. No; this component must hide itself for those states.

Several declarations of useInsightsGetStreak are TypeScript overloads for one function, not several hooks. Skip to its final body: it constructs the generated options, calls useQuery, and returns that query result. That return type is the proof that the hook supplies data, isPending, and isError.

Follow the return type into TanStack Query

The generated hook's signature ends with this return type:

UseQueryResult<TData, TError> & { queryKey: ... }

Orval does not list every property there. UseQueryResult is a type imported from TanStack Query. TanStack defines that result object with properties including data, isPending, isError, error, and many more. Your editor can follow the imported type or show those properties on hover.

Make the object visible before using JavaScript destructuring shorthand:

const query = useInsightsGetStreak({ date });

query.data;
query.isPending;
query.isError;

This later line creates three local variables holding those same properties:

const { data, isPending, isError } = query;

Combining the two lines is only shorthand:

const { data, isPending, isError } = useInsightsGetStreak({ date });

It does not request special output variables from the hook. The hook returns one object; JavaScript destructuring picks three properties off that object.

A repeatable way to choose an export
  1. Find the endpoint's operation words: here, GetStreak.
  2. Discard type aliases and the key/options factories for rendering work.
  3. Choose a use… export because this is a React component.
  4. Choose regular versus Suspense by asking who must own pending and error UI. Issue #271 says this component owns both, so choose the regular hook.
  5. Hover the chosen export and verify its parameter and return types before writing JSX.

Supply the business date

The repository already owns the timezone-sensitive conversion in utils/local-date.ts. Call localIsoDate(). Do not use new Date().toISOString().slice(0, 10): that produces a UTC date, while this endpoint explicitly needs the reader's local calendar date. 

const date = localIsoDate();
const query = useInsightsGetStreak({ date });

This is the only new TanStack Query concept you need for the first pass: the hook starts the query and returns a result object. React renders again when that result changes. Keep the name query at first; destructure it only after its properties feel unsurprising.

Checkpoint before typing

Predict what the component should return for each snapshot:

  1. { data: undefined, isPending: true, isError: false }
  2. { data: undefined, isPending: false, isError: true }
  3. { data: { count: 5, logged_today: false }, ... }
Check your prediction

The first two return null. The third renders the number 5 and the unlit style of the same flame icon. A zero is still successful data and should render 0.

One rule worth retaining

Hooks run at the top level; rendering branches come afterward. React's Rules of Hooks explain the first half, and its conditional rendering guide shows the second. TanStack's query guide documents the pending/error/success state machine used here.

Keep the reusable query-backed component reference nearby while you work.
