Layout reasoning checklist

Use these questions before searching for a utility. They diagnose the relationship that needs styling without prescribing a component-specific class string.

Structure

  1. Which visual elements must move as one group?
  2. Which element should own that group?
  3. What are that owner's direct children?
  4. Does the DOM tree express the same groups as the design?

Axes

  1. Is the main axis a row or a column?
  2. How should free space be distributed along the main axis?
  3. How should differently sized children align along the cross axis?
  4. Does a nested relationship need a different alignment rule?

Sizing and wrapping

  1. Are whole flex items wrapping, or is text wrapping inside one item?
  2. Which sibling should yield space when the container narrows?
  3. Does a compact group need to preserve its intrinsic width?
  4. Is overflow preferable to wrapping at the smallest supported width?

State color

  1. Is the state changing foreground color, background color, or both?
  2. What is the lowest parent that owns every element sharing the state?
  3. Do descendant SVGs use currentColor?
  4. Are all conditional Tailwind class names complete strings in source?
  5. Do the chosen theme tokens work in light and dark modes?

Use alongside Reason about nested flex layouts and Drive inherited color from state.
