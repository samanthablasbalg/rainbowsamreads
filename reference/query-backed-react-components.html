Query-backed component reference

A query-backed component turns one cache entry's lifecycle into UI. Keep these three questions separate: what identifies the data, what state is the request in, and what should this component render for that state?

The component shape

export function Example() {
  const input = deriveRequestInput();
  const query = useGeneratedQuery({ input });

  if (query.isPending || query.isError) return null;

  return <output>{query.data.value}</output>;
}

Call the hook before branching. React requires hooks at the component's top level; the branch controls rendered output, not whether React sees the hook call.

A query hook returns one object. query.data, query.isPending, and query.isError are properties of that object. Writing const { data, isPending, isError } = query is JavaScript shorthand for making local variables from those properties.

Choosing among generated exports

Name shape Meaning Typical consumer
operationName(...) Raw promise-returning HTTP function Imperative or non-React code
get…QueryKey(...) Cache identity factory Invalidation and cache access
get…QueryOptions(...) Key plus query function Prefetching or advanced composition
use…(...) Regular query hook with explicit lifecycle states A component that handles pending/error itself
use…Suspense(...) Suspense query hook A subtree whose boundaries own pending/error UI

Repeated declarations with the exact same function name are usually TypeScript overloads. Find the one final declaration with a body to see the single runtime implementation.

Query identity

request:   GET /thing?date=2026-10-10
query key: ['/thing', { date: '2026-10-10' }]

If a request variable changes the answer, it belongs in the query key. In this repository, Orval's generated key factory already includes the entire params object. Pass the local date into the generated hook; do not construct a second hand-written key in the component.

State-to-UI decision table

Query state Data usable? Typical output
Pending No Placeholder, spinner, or null
Error No Error UI, fallback, or null
Success Yes UI derived from data

The product decides which output is appropriate. Issue #271 explicitly chooses null for both pending and error because the streak is decorative while the reading list is essential.

Invalidation later

queryClient.invalidateQueries({ queryKey: generatedKeyFactory() });

Invalidation does not manually replace the streak count. It marks matching cached data stale and, when the query is active, TanStack Query refetches it. Use the generated key factory so readers and writers refer to the same cache identity.
