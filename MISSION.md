# Mission: Build Reading Tracker Features as the Primary Driver

## Why

Build features in this repository through hands-on implementation, using the agent as a teacher and
reviewer rather than delegating the coding. The goal is to become confident navigating unfamiliar
Python, FastAPI, SQLAlchemy, React, and API-design details while retaining ownership of decisions.

## Success looks like

- Trace a feature through its API, service, domain-model, persistence, frontend, and test layers.
- Distinguish current behavior, stale issue text, open design questions, and pinned decisions.
- Implement and verify repository features with progressively lighter guidance from the agent.

## Constraints

- The user drives code editing; the agent explains, poses focused exercises, and reviews the work.
- Prefer investigation against repository code and primary documentation over unsupported recall.
- Capture durable insights without turning straightforward feature work into a large course.

## Out of scope

- Broad Python or React curricula disconnected from the feature currently being built.
- Having the agent independently implement the feature unless explicitly requested.
